# ISSUE: Потеря данных сканирования при аварийном завершении

**Дата:** 05.01.2026
**Статус:** Resolved (Fixed in v0.2.0)
**Priority:** Critical

## 1. Описание проблемы (Symptoms)

Пользователь запустил сканирование (Скан ID 8). По завершении (или прерывании) в базе данных:
*   Статус скана остался `started`.
*   Таблица `files` для этого `scan_id` **пуста** (0 записей).
*   Таблица `scan_progress` содержит 5746 записей в статусе `in_progress`.

### Анализ
Утилита использует `tmpfs` (/dev/shm) для ускорения записи. Данные сбрасываются на диск (Checkpoint) только при выполнении условий (100 папок или 10к файлов).

**Вероятная причина:**
1.  Процесс был убит (SIGKILL) или завершился аварийно (Exception), не вызвав `atexit` хуки или блок `finally`.
2.  Логика чекпоинтов не сработала, либо транзакция копирования из RAM на Disk откатилась.
3.  Отсутствует механизм восстановления статуса `failed`/`interrupted` при следующем запуске, если предыдущий скан "повис" в `started`.

## 2. Предложения по исправлению (Fix Proposal)

1.  **Atomic Checkpoints:** Убедиться, что `checkpoint_to_disk` коммитит данные чаще или надежнее.
2.  **Crash Recovery:** При старте утилиты проверять наличие "повисших" сканов (статус `started`, но процесс не бежит) и помечать их как `crashed`.
3.  **Force Flush:** При перехвате `KeyboardInterrupt` или любого `Exception` гарантированно вызывать `checkpoint_to_disk(force=True)` **до** закрытия соединений.
4.  **Signal Handling:** Добавить обработчик сигналов `SIGTERM` (помимо `atexit`), чтобы корректно сбрасывать данные при `kill`.

## 3. Требования к новому функционалу (Feature Request)

Для упрощения диагностики и работы с файлами без прямого доступа к SQL.

### А. Расширение `report`
Добавить новые типы отчетов:

**1. `report long-paths`**
*   **Цель:** Найти файлы, превышающие лимит длины пути.
*   **Параметры:** `--limit-chars N` (по умолчанию 240).
*   **Вывод:** Список путей и их длина.
*   **Пример:** `python3 ydm.py report long-paths --scan-id 5`

**2. `report analyze-scan`**
*   **Цель:** Быстрая проверка целостности данных скана.
*   **Вывод:**
    *   Кол-во файлов и папок.
    *   Кол-во записей в `scan_progress` (completed/pending).
    *   Предупреждение, если `files_count=0` при статусе `success/started`.

**3. `report duplicates`**
*   **Цель:** Найти дубликаты (по MD5 или размер+имя).
*   **Полезно:** Для чистки мусора.

### Б. Улучшение UX
*   Добавить в `scan-list` колонку "Files" (уже есть, но убедиться, что она корректна).
*   При запуске `scan` предупреждать, если предыдущий скан завершился некорректно.

## ✅ IMPLEMENTATION SUMMARY (05.01.2026)

Все предложения реализованы. Смотри [FIX_SCAN_DATA_LOSS_IMPLEMENTATION.md](FIX_SCAN_DATA_LOSS_IMPLEMENTATION.md) для деталей.

### Что было сделано:

1. **Signal Handlers** (SIGTERM, SIGUSR1)
   - Добавлены обработчики сигналов для гарантированного checkpoint перед выходом
   - Даже если процесс получит SIGTERM, данные будут сохранены

2. **Crash Recovery**
   - Метод `recover_crashed_scans()` - проверяет и помечает повисшие сканы как 'crashed'
   - Запускается при каждой `scan` команде
   - Выводит список найденных crashed сканов для информирования пользователя

3. **Более частые Checkpoints**
   - Сокращен интервал с 5 минут до **30 секунд**
   - Сокращены пороги (папок: 100→50, файлов: 10k→5k)
   - Добавлена инициализация финальной БД если её нет

4. **Новые Report Команды**
   - `python3 ydm.py report long-paths --scan-id N` - файлы с длинными путями
   - `python3 ydm.py report analyze-scan --scan-id N` - проверка целостности
   - `python3 ydm.py report duplicates --scan-id N` - поиск дубликатов по хешу или имени

5. **Валидация целостности**
   - Предупреждения если `files_count=0` при завершенном скане
   - Информирование о crashed сканах при запуске нового сканирования
   - Проверка `scan_progress` статусов в `analyze-scan` отчете

### Результат:
✅ **Риск потери данных сведен к минимуму**
- Checkpoints каждые 30 сек (было 5 мин)
- Signal handlers ловят SIGTERM
- Crash recovery восстанавливает статусы
- Диагностические отчеты помогают найти проблемы
