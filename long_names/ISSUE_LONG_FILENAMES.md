# Проблема: Ошибки синхронизации из-за длинных имен файлов

*Дата регистрации:* 04.01.2026
*Статус:* **Open**
*Приоритет:* High (блокирует синхронизацию)

## 1. Симптомы
Клиент Яндекс.Диска (`yandex-disk status`) возвращает ошибку `Статус ядра синхронизации: ошибка`.
Причина: `Ошибка: ошибка доступа`.

**Пример проблемного файла:**
```text
/data/ya_disk/Компьютер WIN-15D5F8IN9EB/Books/Math/Zadachi/Математика. Элективные курсы (14 книг) [2008-2016] Шахмейстер/Шахмейстер А. Х. - Построение и преобразования графиков. Параметры. Части 2-3. Нелинейные функции и уравнения. Графическое решение уравнений... - 2016.pdf
```

## 2. Анализ причин
1.  **Длина пути:** Полный путь превышает лимиты файловой системы (обычно 255 байт для имени файла, 4096 для пути) или внутренние буферы клиента синхронизации.
2.  **Спецсимволы/Кодировка:** Использование кириллицы и пробелов в глубокой вложенности увеличивает размер строки в байтах (UTF-8).
3.  **Источник:** Файлы пришли с Windows-машины (`Компьютер WIN-...`), где ограничения NTFS отличаются, но при переносе в Linux/Cloud возникают коллизии.

## 3. Предлагаемое решение (Architecture)

Реализовать **умное массовое переименование** с использованием локального AI.

### Этап А: Анализ (Discovery)
Использовать существующую базу данных `monitor.db`:
1.  Написать SQL-запрос для выборки файлов, где `length(path) > N` (например, 200 символов).
2.  Составить список кандидатов на переименование.

### Этап Б: Инфраструктура AI
Развернуть локальную LLM (Large Language Model) на имеющейся GPU (GTX 1080 Ti).
*   **Инструмент:** [Ollama](https://ollama.com).
*   **Модель:** `llama3` или `qwen2.5` (7B quantized).
*   **Преимущества:** Бесплатно, приватно, не требует интернета/API-ключей.

### Этап В: Скрипт `smart_renamer.py`
Скрипт должен:
1.  Брать длинное имя файла.
2.  Отправлять промпт в Ollama:
    > "Переименуй файл: '{filename}'. Сделай имя коротким, на английском (transliteration/translation), сохранив смысловую суть, расширение и год. Используй snake_case. Максимум 50 символов."
3.  Получать ответ (например: `shahmeister_graph_transform_part2-3_2016.pdf`).
4.  Сохранять маппинг `old_path -> new_path` в JSON/DB для ревью.

### Этап Г: Исполнение (Execution)
1.  **Dry Run:** Показать пользователю таблицу "Было -> Стало".
2.  **Apply:** Переименовать файлы локально.
3.  **Sync:** Дождаться, пока клиент Яндекс.Диска подхватит изменения (удалит длинное, загрузит короткое).

## 4. План реализации
1.  [ ] Установить Ollama (`curl -fsSL https://ollama.com/install.sh | sh`).
2.  [ ] Скачать модель (`ollama pull llama3`).
3.  [ ] Написать прототип скрипта `smart_renamer.py`.
