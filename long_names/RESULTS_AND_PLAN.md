*Документация по проблеме:* [ISSUE_LONG_FILENAMES.md](./ISSUE_LONG_FILENAMES.md)

## 1. Текущие результаты (05.01.2026)

### Техническое подтверждение
В ходе анализа базы данных `monitor.db` и файловой системы были подтверждены следующие факты:
*   **Причина сбоя:** Официальный клиент `yandex-disk` падает с "ошибкой доступа", так как пытается создать файлы, чьи имена (не пути, а именно имена) превышают лимит файловой системы Linux (ext4).
*   **Лимиты:** Лимит ext4 на имя файла составляет **255 байт**.
*   **Обнаруженные аномалии:** В облаке Яндекс.Диска хранятся файлы с именами до **364 байт**. 
*   **Доступность данных:** Утилита `ydm.py` успешно считывает эти имена через API и сохраняет их в базу данных. Это означает, что `monitor.db` является полным и достоверным источником имен для обработки.
*   **Физическое отсутствие:** Команда `ls` подтвердила, что файлы с именами > 255 байт отсутствуют на локальном диске, хотя числятся в облаке.

### Статистика (Скан №5)
*   Файлов с именами > 140 байт: **~100+ штук**.
*   Максимальная длина имени: **364 байта**.
*   Категории: Приказы, учебники (Шахмейстер), видеолекции, ресурсы сохраненных web-страниц.

## 2. План действий (Next Steps)

### Шаг 1: Инфраструктура (Ollama)
*   **Статус:** Установлено.
*   **Действие:** Загрузить и протестировать модель `qwen2.5:7b` или `llama3`.
*   **Локация:** `/data/infra/ai_services/ollama`.

### Шаг 2: Разработка Smart Renamer
*   Создать Python-скрипт `smart_renamer.py` в этой папке.
*   **Логика:**
    1.  Выборка из `monitor.db` всех имен файлов > 140 байт.
    2.  Генерация нового имени через API Ollama (сокращение + транслитерация).
    3.  Исключение из обработки ресурсов web-страниц (папки `*_files`).
    4.  Формирование JSON-отчета с предложением переименований.

### Шаг 3: Переименование в облаке
*   **Важно:** Переименовывать нужно **в облаке через API**, а не локально (так как локально файлов просто нет).
*   После успешного выполнения `MOVE` (rename) через API, локальный клиент `yandex-disk` автоматически скачает файлы с новыми короткими именами.

### Шаг 4: Верификация
*   Проверка статуса `yandex-disk status`.
*   Убедиться, что "ошибка доступа" исчезла и файлы скачались.
