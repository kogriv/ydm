# Импорт файла с другого устройства — Design

*Backlog:* [`BACKLOG.md`](./BACKLOG.md), 4.6
*Статус:* реализовано (`sync_policy.py import-file`)

## Задача

Облако перечисляет файл, но не отдаёт его (500/503), а на другом устройстве
владельца есть копия. Файл должен попасть в зеркало этой машины так, чтобы было
доказано: это тот самый файл, а не другой с тем же именем.

Раньше это делалось вручную мимо YDM: скопировать, посчитать md5, сравнить с
облаком, снять карантин.

## Что команда делает

```
sync_policy.py import-file --source <файл на этой машине> --path /Папка/файл [--apply]
```

1. Путь лежит внутри синхронизируемой папки, иначе отказ.
2. `rclone lsjson --stat --hash` даёт md5 и дату файла в облаке. Содержимое не
   запрашивается, поэтому команда работает и для файла, который облако не отдаёт.
3. md5 источника равен md5 облака, иначе отказ. Файла без md5 в облаке не берём.
4. В зеркале такого файла нет. Такой же файл даёт `already_there`, другой — отказ.
5. С `--apply` файл копируется в зеркало под блокировкой bisync. Дата ставится
   из облака, иначе следующий resync примет копию за более новую и отправит её
   обратно. Источник остаётся на месте.

Без `--apply` выполняются все проверки, кроме записи.

## Чего команда не делает, намеренно

- **Не ходит на другое устройство.** Доступ к чужому устройству — решение его
  владельца: у него может идти свой синк, у него своя сессия. Как файл оказался
  на этой машине, команду не касается: `--source` принимает только локальный путь.
- **Не пишет в облако.** Несовпавшую копию нельзя загрузить поверх, а совпавшая
  там уже есть. Замена содержимого в облаке — отдельное решение человека.
- **Не снимает карантин.** Это меняет фильтр и требует resync; шаги приходят в
  `data.next`. Сначала человек или агент видит результат импорта.

## Границы

- Совпадение md5 доказывает содержимое, а не то, что облако когда-нибудь снова
  отдаст файл. Если оно его потеряло, файл в зеркале станет единственной копией.
- Запись защищена блокировкой, потому что вне карантина файл виден bisync: без неё
  запуск мог бы подхватить недописанную копию. Занятая блокировка даёт код 3.
- На Android имена могут отличаться от облачных из-за запрещённых символов. Такие
  файлы в режим `bidirectional` не попадают, поэтому команда этот случай не решает.
