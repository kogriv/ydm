## Суть

Весь август строилось одно правило: **частичный скан не может быть базой
композита**. Скан, запущенный как `--path /Books`, ничего не знает про
остальной диск; сделать его базой — значит объявить, что диск состоит из
`/Books`. Ровно это и случилось 16.08: `sync_tree --path /` показал одного
ребёнка.

Гейт написан и работает — `Analyzer.scan_covers_root()`, и `find_last_full_scan()`
через него отсеивает всё, что корень не покрывает.

**Но в `build_composite_scan()` есть путь, который гейт не проходит вовсе.**

```python
base_scan = self.find_last_full_scan(cloud_scan_id)
if not base_scan or "error" in base_scan:
    # Fallback: try to use the last cloud scan as base (old behavior)
    last_cloud = conn.execute(
        "SELECT id, timestamp, status FROM scans "
        "WHERE scan_type = 'cloud' ORDER BY id DESC LIMIT 1"
    ).fetchone()
    ...
    base_scan = {...}      # ← ни проверки покрытия, ни проверки статуса
```

`ydm.py:1912`. Берётся **последний облачный скан, какой есть**.

## Почему это опаснее, чем выглядит

Дело во времени срабатывания. `find_last_full_scan()` возвращает `None` ровно
тогда, когда **гейт отверг всё** — годного скана нет. И именно в этот момент
запасной путь отключает проверку и ставит базой то, что только что забраковали.

То есть защита выключается в единственной ситуации, ради которой её писали.

Что может попасть в базу через этот путь:

- частичный скан (`--path /Books`) — ровно то, от чего гейт;
- скан с ограничением глубины (`--depth 1`) — их завели 23.08, такой скан
  корня содержит 3 файла и станет базой всего снимка;
- скан со статусом `crashed` или `started` — статус не проверяется.

## Воспроизведение

Синтетическая база, в которой нет ни одного полного скана:

```
scan 1: cloud, success, scan_root=/Books           (5 файлов)
scan 2: cloud, success, scan_root=/, scan_depth=1  (1 файл)
```

```
find_last_full_scan  : None      ← гейт: годной базы нет
find_last_root_scan  : None      ← и здесь нет
composite base       : 2         ← база всё равно назначена
covers_root(base)    : False     ← это скан, который гейт отверг
```

Ни ошибки, ни предупреждения. Снимок всего диска — один файл.

## Почему не стреляет сегодня

Скан #72 существует и гейт проходит. Мина сработает, когда полного скана не
станет: после `report prune` с агрессивными настройками, при переносе базы,
на новой машине, где сначала сделали пару частичных сканов.

## Что должно быть вместо

Запасной путь имеет право ослаблять **мягкий** критерий (свежесть) и не имеет
права ослаблять **жёсткий** (покрытие корня). Это различение уже реализовано
внутри `find_last_full_scan()`: если свежих кандидатов нет, он берёт
`find_last_root_scan()` — самый свежий из покрывающих корень, пусть и старый.
`None` он возвращает только когда корень не покрывает вообще никто.

Значит, `None` от него — это не «попробуй что-нибудь ещё», а **окончательный
ответ**: базы нет. Композит должен вернуть ошибку, а не подставлять что попало.

Все вызывающие ошибку уже переживают:

| Вызывающий | Поведение на ошибке |
|---|---|
| `ydm.py get_diff()` | падает в `_compare_simple_scan()` — честное сравнение по одному скану, явно помеченное |
| `tools/cloud_delta.py` | `CloudDeltaError` с текстом |
| `tools/sync_common.py` | `RuntimeError` — но текст теряет причину, надо поправить |
| `snapshot_freshness()`, `prune_plan()` | пробрасывают `{"error": ...}` |
