# Sync Bench — Design

*Дата:* 2026-08-23
*Зависимости:* `tools/sync_tree.py`, `tools/sync_tree_policy.py`,
`tools/sync_common.py`, `tools/ydm_menu*.py`, `ydm.py` (`StorageManager`,
`Analyzer`)
*Разбор проблемы:* [`GAP.md`](./GAP.md)

## Goals

1. **Сквозная проверка вместо послойной.** Тест начинается с файлов на диске
   (политика, локальные папки, БД) и заканчивается строкой вывода — так же,
   как это происходит у пользователя.
2. **Ни одна проверка не трогает боевое.** Ни `var/sync_policy.json`, ни
   `~/.config/yandex-disk/config.cfg`, ни `monitor.db`, ни `/data/ya_disk`.
3. **Стенд один на дерево и на меню.** Оба читают одни и те же источники;
   два разных фикстура разошлись бы, и проверялись бы две разные системы.
4. **Все девять маркеров.** Включая `[.]`, в который проваливается всё
   непопавшее в предыдущие ветки.
5. **Работает в CI.** Без сети, без демона, без rclone, с пустым `HOME`.

## Non-goals

- Не заменять юнит-тесты `display_marker()` — они дешёвые и остаются.
- Не проверять реальный обмен данными: bisync, копирование, работу демона.
  Стенд отвечает на вопрос «что система *говорит*», не «что она делает с
  файлами».
- Не воспроизводить Android. Проверка `ydm-menu` через rclone на устройстве
  остаётся заблокированной второй машиной — стенд её не подменяет и не
  притворяется, что подменяет.
- Не менять формат `sync_policy.json` и схему `sync_tree:v2`.

---

## Ключевое решение: стенд, а не боевая конфигурация

Разобрано в [`GAP.md#g4`](./GAP.md). Коротко: чтобы увидеть `[B]` под `Books`
на боевом демоне, надо начать реальную синхронизацию `/Books` — операцию из
инцидента 14.08. Соразмерности нет.

Отвергнутые варианты:

| Вариант | Почему нет |
|---|---|
| Прогонять чек-листы на боевой политике | G4: движение боевых данных ради проверки рендера |
| Отдельная «тестовая» папка в облаке | Требует сети и токена в CI; мусор в облаке; не покрывает `[L]` (локальная сирота без облака) |
| Мокать `display_marker()` на уровне вызова | Ровно то, что уже есть, и ровно то, что не работает: стык слоёв остаётся непроверенным |
| Снимок боевой БД как фикстур | 128 МБ в репозитории; данные пользователя в git; хрупко к prune |

## Устройство стенда

Всё во временной директории, создаётся кодом, живёт один тест.

```text
<tmp>/
  policy.json          политика: записи всех трёх режимов + пропуски
  local/               «диск»: материализованные папки, частичные, сироты
    pro/agents/…
    Books/Math/АнГем/  сирота: есть локально, нет в политике
  monitor.db           снимок облака: один полный скан + частичные
  config.cfg           exclude-dirs для daemon-семантики
```

### Дерево-образец

Одно дерево должно давать все девять маркеров. Минимальный набор:

| Путь | В политике | Локально | В облаке | Ожидаемый маркер |
|---|---|---|---|---|
| `/pro` | bidirectional | всё | всё | `[B]` |
| `/pro/agents` | bidirectional | ничего | есть | `[B?]` |
| `/video` | bidirectional | часть | всё | `[B~]` |
| `/Docs` | download_only | всё | всё | `[D]` |
| `/Docs/arch` | download_only | ничего | есть | `[D?]` |
| `/Books` | disabled | — | есть | `[X]` |
| `/mix` | нет | — | есть | `[P]` (внутри есть синхронизируемое) |
| `/mix/inner` | bidirectional | всё | есть | `[B]` |
| `/Books/Math/АнГем` | нет | есть | нет | `[L]` |
| `/arch` | нет | нет | есть | `[.]` |

`[P]` требует, чтобы у `/mix` не было своей записи, а у потомка была — иначе
ветка не достигается.

### Две семантики политики

`PolicyContext.blacklist_semantics` разводит бэкенды: для демона всё, чего нет
в `exclude-dirs`, синхронизируется; для rclone — наоборот, синхронизируется
только перечисленное. Одна и та же папка получает разные маркеры.

Стенд параметризуется по бэкенду и прогоняет обе. Это не удвоение работы —
таблица выше строится один раз, ожидания различаются в нескольких строках.

## Уровни проверки

Три, от дешёвого к дорогому. Каждый ловит своё; отсутствие любого — дыра из
`GAP.md`.

**Уровень 1 — таблица истинности `display_marker()`.** Есть, дополняется до
девяти значений. Ловит ошибку в порядке ветвлений.

**Уровень 2 — стенд → маркеры.** Строится дерево из файлов стенда, сверяется
`путь → маркер` по таблице. Ловит то, чего не ловит уровень 1: неверные
аргументы, дошедшие до правильной функции. Это дефект `parent_path`, повторно.

**Уровень 3 — стенд → процесс.** `subprocess` на `sync_tree.py` и
`ydm_menu.py --non-interactive` с путями стенда, разбор stdout. Ловит то, что
не видно изнутри процесса: разбор аргументов, значения по умолчанию, JSON
schema, поведение при отсутствии локального скана.

## Меню на стенде

`ydm_menu` уже принимает `--db-path`, `--local-root`, `--policy-path`,
`--bisync-filter-path`, `--backend`, `--non-interactive` — то есть **полностью
адресуется на стенд без единой правки**. Это и делает работу дешёвой.

Проверяемое без интерактива:

| Пункт меню | Что проверяется |
|---|---|
| шапка | совпадает с фактами политики и снимка |
| 1 Show sync tree | те же маркеры, что уровень 2 |
| 3 Add LOCAL folder | `orphans` находит `Books/Math/АнГем` |
| 4 Remove folder | политика на стенде изменилась, боевая — нет |
| 7 Cloud scan | предлагается, когда снимок устарел |
| 8 Detailed status | не падает при `backend_error` |

Что остаётся вне стенда и почему:

| Пункт | Причина |
|---|---|
| 5 Restart daemon / Run bisync | реальный процесс; стенд не отвечает на «что делает» |
| 6 Resync baseline | то же |
| Android через rclone | нужна вторая машина; см. `tasks/sync_unification` |

Честность здесь важнее охвата: чек-лист, где часть пунктов помечена
«проверено» стендом, который их не проверяет, хуже пустого.

## Как чек-листы перестанут протухать

Причина протухания (`GAP.md#g3`) — привязка к живому состоянию: `Books/Math/База`
исчезла из политики, и пункт стал невыполним молча.

Пункты, привязанные к стенду, ломаются **громко**: стенд создаётся кодом, и
если ожидание разошлось с поведением, падает тест, а не тихо устаревает
галочка. Поэтому старые чек-листы не переписываются, а **заменяются ссылкой на
тесты**; в виде списка остаётся только то, что действительно требует человека и
устройства.

## Риски

| Риск | Что делаем |
|---|---|
| Стенд повторяет реализацию, а не требования, и проходит на сломанном коде | Таблица `путь → маркер` пишется от того, что *должен* увидеть человек, до запуска кода; расхождение разбирается, а не подгоняется |
| Фикстур обрастает и становится вторым источником правды | Один стенд, одна таблица, оба слоя читают её |
| `subprocess`-тесты медленные | Уровень 3 — несколько вызовов, не по одному на случай |
| Локальные папки в `tmp` не воспроизводят Android FS | Явно вне охвата; Android остаётся ручной проверкой |
| Проверка случайно возьмёт боевые пути | Все пути передаются явно; отдельный тест, что при подмене `HOME` и путей стенда ни `var/sync_policy.json`, ни `monitor.db` не открываются |
