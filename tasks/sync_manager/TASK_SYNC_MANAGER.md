# Задача: Утилита управления синхронизацией Yandex Disk

*Дата регистрации:* 06.01.2026  
*Статус:* **Open**  
*Приоритет:* Medium (удобство управления)

---

## 1. Проблема

### Текущая ситуация
Управление синхронизацией Yandex Disk происходит через редактирование конфига `~/.config/yandex-disk/config.cfg` вручную. Это создает несколько проблем:

1. **Нет визуализации:** Непонятно, какие папки фактически синхронизируются сейчас
   - Конфиг содержит только список исключений (`exclude-dirs`)
   - Чтобы понять, что синхронизируется, нужно мысленно "вычесть" исключения из всех папок облака
   - Нет дерева структуры синхронизируемых папок

2. **Сложность добавления подпапок:** 
   - Для синхронизации только одной подпапки (например, `video/n8n`) нужно:
     - Убрать родительскую папку (`video`) из exclude-dirs
     - Добавить все остальные подпапки (`video/sub1`, `video/sub2`, ...) в exclude-dirs
   - При большом количестве подпапок это трудоемко и подвержено ошибкам
   - Нет автоматизации этого процесса

3. **Опасные имена папок:**
   - Имена с запятыми (`MBA, PhD`) разбивают exclude-dirs на части
   - Имена с квадратными скобками `[ ]` могут вызывать проблемы
   - Нет предупреждений о таких именах при добавлении в синхронизацию

4. **Отсутствие обзора структуры:**
   - Невозможно быстро посмотреть структуру папки в облаке
   - Непонятно, какие подпапки есть и какие из них синхронизируются

5. **Проблема с исключением файлов (ПРОВЕРЕНО):**
   - ❌ **`exclude-dirs` НЕ работает для файлов!**
   - Файлы в корне синхронизируемой папки синхронизируются всегда
   - Даже если файл добавлен в `exclude-dirs`, он все равно синхронизируется
   - **Решение:** Переместить файл в исключенную подпапку через API

6. **Двусторонняя синхронизация:**
   - ⚠️ **Важно:** Удаление файла локально (`rm`) приводит к удалению в облаке!
   - Это стандартное поведение yandex-disk на всех платформах (Windows, Linux, macOS)
   - `exclude-dirs` работает односторонне (папка не синхронизируется)
   - Удаление локально работает двусторонне (удаляется везде)

## 2. Предлагаемое решение

Создать утилиту `sync_manager.py` (или расширение для `ydm.py`) для управления синхронизацией.

### Двухуровневая архитектура данных

Sync-manager **не сканирует облако** — сканирование облака длительная операция (до нескольких часов), при работе sync-manager нужна скорость.

- **Уровень 1 (долгий):** сканы облака и (опционально) локалки с записью в БД. Выполняются отдельно (cron, ручной запуск и т.п.).
- **Уровень 2:** sync-manager работает **только со снимками** — дерево облака и при необходимости дерево локалки берутся из БД (последний полный/композитный cloud scan; при необходимости последний local scan).
- **Локальный скан при старте:** допустимо и целесообразно **опционально (по умолчанию)** запускать скан локалки при запуске sync-manager, т.к. это быстрая процедура. Облако при этом не сканируется.
- **Метаданные о свежести:** необходимо предусмотреть сообщения (метаданные) о свежести сканов. Если пользователь меняет конфиг исключений (добавляет/убирает папки из sync), нужно записывать или выводить информацию об этих изменениях и о том, когда были сделаны снимки облака и локалки, чтобы было понятно, насколько актуальны отображаемые деревья. Цель — пользователь всегда понимает актуальность снимков.

### Два уровня интерфейса (без интерактивности)

- **Базовый CLI (automation / assistant‑friendly):** однозначные команды, предсказуемые параметры, структурированный вывод (JSON или стабильный текст). Для скриптов, cron, CI, ассистентов. Никаких диалогов «нажмите Enter» или «Применить? [y/N]» — только флаги (например, `--apply`, `--dry-run`).
- **Человекочитаемый вывод:** текстовое дерево с маркерами синхронизации, свернутое по умолчанию; развертывание через `--path` и `--depth`. Управление только аргументами CLI.

### Функционал

#### 2.1. Дерево облака со статусом синхронизации (полная иерархия)

**Команда:** `ydm.py sync tree [--path PATH] [--depth N] [--format json|text]`

**Суть:** показывать **всё дерево папок облака** с пометкой по каждой папке: участвует ли она в синхронизации и как именно (полностью / частично / исключена). Не только «синхронизируемые» папки, а полная иерархия с маркерами.

**Правила маркеров по иерархии:**
- **Полностью синхронизируется** (вся папка и всё содержимое в sync): один маркер, например `[S]` (sync).
- **Частично синхронизируется** (папка в exclude-dirs, но есть включённые подпапки): другой маркер, например `[P]` (partial).
- **Исключена из синхронизации** (папка в исключениях и ни одна дочерняя не включена): третий маркер, например `[-]`.

**Пример иерархии:** `books` → partial, `books/math` → partial, `books/math/linal` → partial, `books/math/linal/strfng` → sync. Для каждой папки в выводе — соответствующий знак.

**Параметры:**
- Без `--path`: дерево от корня облака.
- С `--path`: поддерево от указанной папки (для развернутого просмотра).
- `--depth`: максимальная глубина (по умолчанию свернутый вид, например `--depth 1` или `2`).
- `--format json`: машиночитаемая структура (см. ниже).
- `--format text`: человекочитаемое дерево с маркерами `[S]` / `[P]` / `[-]`.

**Вывод JSON (схема узла):** `path`, `name`, `sync_status` (`full` | `partial` | `excluded`), опционально `has_local`, `children` (если не свернуто) или `children_count`.

**Вывод text (пример):**
```
[S] /
[P] Books
[P]   math
[P]     linal
[S]       strfng
[-] video
[-]   tmp
```

**Источники данных:** дерево папок облака **только из БД** (последний полный/композитный cloud scan; сканирование облака при работе sync-manager не выполняется); список исключений из `~/.config/yandex-disk/config.cfg`. Опционально — снимок локалки из БД (при необходимости флаг «есть локально»). В выводе или метаданных — информация о свежести использованных снимков (дата/время сканов).

#### 2.2. Просмотр структуры папки с предупреждениями
**Команда:** `python3 sync_manager.py inspect --path /video` или `python3 ydm.py sync inspect --path /video`

**Вывод:** Список подпапок и файлов с указанием опасных имен
```
Структура папки /video:
├── n8n/                          [СИНХРОНИЗИРУЕТСЯ]
├── Blender/                       [ИСКЛЮЧЕНО]
├── 3ds Max/                       [ИСКЛЮЧЕНО]
├── [Bogdan...] Docker/            [ИСКЛЮЧЕНО] ⚠️ ОПАСНО: содержит [ ]
├── Математика/                    [ИСКЛЮЧЕНО]
├── test-draiv_3007.avi           [СИНХРОНИЗИРУЕТСЯ] ⚠️ Файл в корне
└── ...

⚠️ Предупреждения:
  - [Bogdan...] Docker: содержит квадратные скобки [ ]
  - Алгебра_и_геометрия: содержит запятые (может разбить exclude-dirs)
  - test-draiv_3007.avi: файл в корне папки (нельзя исключить через exclude-dirs)
```

**Логика:**
- Получает список подпапок и файлов **из снимка облака в БД** (без сканирования облака)
- Проверяет статус каждой (синхронизируется/исключена) по конфигу
- Анализирует имена на опасные символы:
  - Запятые `,` - разбивают exclude-dirs
  - Квадратные скобки `[ ]` - могут вызывать проблемы
  - Длинные имена (>200 символов)
- **Предупреждает о файлах в корне** синхронизируемой папки (их нельзя исключить)

#### 2.3. Добавление папки в синхронизацию
**Команда:** `python3 sync_manager.py add --path /video/n8n` или `python3 ydm.py sync add --path /video/n8n`

**Действия:**
1. Проверяет, что папка существует **в снимке облака (БД)** (без сканирования облака)
2. Анализирует имя на опасные символы (предупреждает)
3. Если родительская папка (`video`) в exclude-dirs:
   - Убирает родительскую из exclude-dirs
   - Получает список всех подпапок родительской **из снимка в БД**
   - Добавляет все подпапки КРОМЕ указанной в exclude-dirs
4. Если родительская НЕ в exclude-dirs:
   - Просто добавляет указанную папку в exclude-dirs (чтобы исключить остальные)
5. По умолчанию **только dry-run**: выводит план изменений (машиночитаемо: JSON или стабильный текст «было / стало» или «что было бы изменено»). **Без интерактивных запросов.**
6. Запись конфига — только по явной команде, например `--apply` (или отдельный флаг). После изменения конфига клиент Yandex Disk нужно перезапустить/перечитать конфиг (отдельная тема: перезапуск сервиса, сигнал и т.д.).

**Пример (dry-run по умолчанию, без запроса подтверждения):**
```bash
$ python3 ydm.py sync add --path /video/n8n

Анализ:
  Папка: /video/n8n
  Родитель: /video (сейчас в exclude-dirs)
  Подпапок в /video: 19

План изменений (dry-run, конфиг не изменён):
  - Убрать из exclude-dirs: video
  - Добавить в exclude-dirs: 
    * video/Blender
    * video/3ds Max
    * video/DS
    * ... (17 подпапок, кроме n8n)

⚠️ Предупреждение: 
  - video/[Bogdan...]: содержит квадратные скобки - может не работать

Для применения выполните: ydm.py sync add --path /video/n8n --apply
```

```bash
$ python3 ydm.py sync add --path /video/n8n --apply
✓ Конфиг обновлен
✓ Yandex-disk перезапущен
```

## 3. Архитектура решения

### 3.1. Модули

1. **ConfigManager** — работа с конфигом yandex-disk
   - Чтение/запись `~/.config/yandex-disk/config.cfg`
   - Парсинг exclude-dirs
   - Валидация изменений

2. **CloudSnapshot (работа со снимками облака)** — дерево облака **только из БД**
   - Использование последнего полного/композитного cloud scan (smart diff и т.п.)
   - Построение дерева папок из данных БД, без вызовов API сканирования облака
   - Сканирование облака не входит в sync-manager (долгая операция, выполняется отдельно)

3. **LocalSnapshot (опционально)** — снимок локальной ФС
   - Опционально (по умолчанию) — запуск локального скана при старте sync-manager (быстрая процедура)
   - Использование снимка из БД для флагов «есть локально» в дереве и отчётах

4. **SyncAnalyzer** — анализ синхронизации
   - Определение статуса папки (full / partial / excluded) по конфигу и иерархии
   - Построение дерева с маркерами [S]/[P]/[-]
   - Детекция опасных имён

5. **SyncManager** — управление синхронизацией
   - Добавление/удаление папки в синхронизацию (правка exclude-dirs)
   - Автоматическое исключение остальных подпапок при add
   - Dry-run по умолчанию, запись конфига по явному флагу

6. **Метаданные о свежести сканов**
   - При выводе дерева/отчётов — сообщения о том, какие снимки использованы (дата/время cloud и при необходимости local scan)
   - При изменении конфига (sync add/remove с `--apply`) — запись или вывод информации об изменении exclude-dirs и рекомендация об актуальности снимков (например: «после изменения набора синхронизируемых папок имеет смысл обновить снимки» или вывод дат использованных снимков)
   - Цель: пользователь всегда понимает, насколько актуальны отображаемые облачное и локальное деревья

### 3.2. Интеграция с ydm.py

**Вариант А:** Отдельный скрипт `sync_manager.py`
- Независимый модуль
- Можно использовать отдельно

**Вариант Б:** Расширение `ydm.py` с командой `sync`
- Интеграция в существующую утилиту
- Единая точка входа

**Рекомендация:** Вариант Б (расширение `ydm.py`) - логично, так как уже есть работа с API и конфигами.

## 4. Технические детали

### 4.1. Парсинг exclude-dirs

**Проблема:** Запятые в именах папок разбивают строку
```
exclude-dirs=video/Blender,video/Test, MBA, PhD,video/n8n
```
Разобьется на: `video/Blender`, `video/Test`, ` MBA`, ` PhD`, `video/n8n`

**Решение:** 
- При чтении конфига проверять, является ли часть пути валидной
- Если нет - объединять с предыдущей частью
- При записи - экранировать запятые или переименовывать папки

### 4.2. Определение статуса папки

**Логика:**
1. Если папка в exclude-dirs → исключена
2. Если родительская папка в exclude-dirs → исключена
3. Если подпапка в exclude-dirs → родительская синхронизируется частично
4. Иначе → синхронизируется

### 4.3. Опасные имена

**Детекция:**
- Запятые `,` - критично (разбивают exclude-dirs)
- Квадратные скобки `[ ]` - предупреждение (могут вызывать проблемы)
- Длинные имена (>200 символов) - предупреждение (проблемы с файловой системой)

## 6. Примеры использования

### Просмотр дерева синхронизации
```bash
python3 ydm.py sync tree
```

### Инспекция папки
```bash
python3 ydm.py sync inspect --path /video
```

### Добавление папки в синхронизацию
```bash
# Dry-run (показывает план, не применяет)
python3 ydm.py sync add --path /video/n8n

python3 ydm.py sync add --path /video/n8n --apply
```

```bash
python3 ydm.py sync remove --path /video/n8n
```

```bash
# Переместить файл в исключенную папку
python3 ydm.py sync exclude-file --path /video/test.avi --move-to /video/excluded_files

# Или создать папку excluded_files и переместить туда
python3 ydm.py sync exclude-file --path /video/test.avi
```

**Примечание:** Так как `exclude-dirs` не работает для файлов, файл перемещается в исключенную подпапку через API.

## 8. Примечания

- **Данные:** sync-manager работает **только со снимками** облака и (опционально) локалки из БД. Сканирование облака при работе sync-manager **не выполняется** (долгая операция). Сканы облака и локалки делаются отдельно (уровень 1); sync-manager — уровень 2 (правка exclude-dirs на основе уже имеющихся снимков). Локальный скан при старте sync-manager допустим и целесообразен (быстрая процедура).
- Утилита должна работать только с конфигом, не изменяя файлы в облаке (кроме случая исключения файлов — см. ниже).
- **Исключение:** Для исключения файлов из синхронизации нужно перемещать их в исключенные папки через API.
- Все изменения конфига должны быть обратимыми (бэкап перед изменениями).
- Dry-run по умолчанию для безопасности.
- Предупреждения о потенциальных проблемах (опасные имена, конфликты).
- **Метаданные о свежести:** при выводе дерева/отчётов и при изменении конфига — сообщения о том, какие снимки использованы и насколько они актуальны, чтобы пользователь понимал релевантность отображаемых данных.

## 9. Важные особенности yandex-disk

### 9.1. Двусторонняя синхронизация
- ⚠️ **Удаление файла локально (`rm`) приводит к удалению в облаке!**
- Это стандартное поведение на всех платформах (Windows, Linux, macOS)
- Если нужно удалить только локально, но оставить в облаке - используйте `exclude-dirs` (для папок)

### 9.2. Исключение файлов (ПРОВЕРЕНО ПРАКТИЧЕСКИ)
- ❌ **`exclude-dirs` НЕ работает для файлов!**
- **Тестирование (06.01.2026):**
  - Добавление `video/m.jpg` в `exclude-dirs` не предотвратило синхронизацию
  - Файл синхронизировался из облака, несмотря на правило исключения
  - **Вывод:** `exclude-dirs` игнорирует файлы, работает только для папок
  
- **Решение для исключения файлов:**
  - Переместить файл в исключенную подпапку через API
  - Пример: файл `video/test.avi` → переместить в `video/excluded_files/test.avi` (где `video/excluded_files` в `exclude-dirs`)
  - Или удалить файл в облаке через API

### 9.3. Переименование в облаке
- При переименовании папки/файла в облаке через API:
  - Локальная копия со старым именем удаляется автоматически
  - Новая папка/файл не загрузится, если она в `exclude-dirs` (для папок)
