## 1. Текущие результаты (05.01.2026)

### Техническое подтверждение
В ходе анализа базы данных `monitor.db` и файловой системы были подтверждены следующие факты:
*   **Причина сбоя:** Официальный клиент `yandex-disk` падает с "ошибкой доступа", так как пытается создать файлы, чьи имена (не пути, а именно имена) превышают лимит файловой системы Linux (ext4).
*   **Лимиты:** Лимит ext4 на имя файла составляет **255 байт**.
*   **Обнаруженные аномалии:** В облаке Яндекс.Диска хранятся файлы с именами до **364 байт**. 
*   **Доступность данных:** Утилита `ydm.py` успешно считывает эти имена через API и сохраняет их в базу данных. Это означает, что `monitor.db` является полным и достоверным источником имен для обработки.
*   **Физическое отсутствие:** Команда `ls` подтвердила, что файлы с именами > 255 байт отсутствуют на локальном диске, хотя числятся в облаке.

### Статистика (Скан №5)
*   Файлов с именами > 140 байт: **~100+ штук**.
*   Максимальная длина имени: **364 байта**.
*   Категории: Приказы, учебники (Шахмейстер), видеолекции, ресурсы сохраненных web-страниц.

## 3. Потенциальные проблемы и решения

### Проблема 1: Конфликты имен
**Описание:** AI может сгенерировать одинаковые короткие имена для разных файлов в одной папке.

**Пример:**
```
Исходные файлы:
- Шахмейстер А. Х. - Построение и преобразования графиков. Параметры. Части 2-3. Нелинейные функции и уравнения. Графическое решение уравнений... - 2016.pdf
- Шахмейстер А. Х. - Построение и преобразования графиков. Параметры. Части 4-5. Системы уравнений. Задачи с параметрами - 2016.pdf

AI может сократить оба до:
- shahmeister_graph_transform_2016.pdf  ← КОНФЛИКТ!
- shahmeister_graph_transform_2016.pdf  ← КОНФЛИКТ!
```

**Решение:**
1. **Детекция конфликтов:** Проверять уникальность новых имен в рамках одной папки.
2. **Автодобавление суффикса:** Если конфликт обнаружен, добавить порядковый номер:
   ```
   shahmeister_graph_transform_part2-3_2016.pdf
   shahmeister_graph_transform_part4-5_2016.pdf
   ```
3. **Улучшение промпта:** Указать AI сохранять различающиеся детали (номер части, главу и т.д.).

**Реализация:**
```python
# Словарь для отслеживания: {folder_path: {new_name: count}}
name_registry = {}

def ensure_unique_name(folder_path, proposed_name):
    if folder_path not in name_registry:
        name_registry[folder_path] = {}

    if proposed_name in name_registry[folder_path]:
        # Конфликт! Добавляем суффикс
        count = name_registry[folder_path][proposed_name] + 1
        name_registry[folder_path][proposed_name] = count
        base, ext = os.path.splitext(proposed_name)
        return f"{base}_{count}{ext}"
    else:
        name_registry[folder_path][proposed_name] = 1
        return proposed_name
```

### Проблема 2: Веб-ресурсы (папки `*_files/`)
**Описание:** Сохраненные веб-страницы создают папки вида `page_files/` с сотнями автогенерированных файлов (`script_1.js`, `image_042.png` и т.д.). Переименовывать каждый файл внутри нецелесообразно.

**Пример структуры:**
```
/Компьютер WIN-.../Saved Pages/
├── Важная статья.html               (короткое имя)
└── Важная статья_files/              (папка ресурсов)
    ├── stylesheet_42_very_long_autogenerated_name_from_cdn.css  ← 200+ байт
    ├── tracker_analytics_script_minified_v2.js                  ← 180+ байт
    └── ... (еще 50+ файлов)
```

**Решение:**
1. **Исключить из обработки:** Не переименовывать файлы внутри папок, оканчивающихся на `_files/`.
2. **Переименовать саму папку:** Если папка `*_files/` имеет длинное имя, сократить имя ПАПКИ:
   ```sql
   SELECT parent_path, name FROM files
   WHERE type='dir' AND name LIKE '%_files' AND LENGTH(name) > 140
   ```
3. **Альтернатива:** Попросить AI предложить переименование только для родительской HTML-страницы, папка автоматически переименуется вместе с ней.

**Фильтр в запросе:**
```python
# Исключить файлы внутри *_files/ папок
excluded_patterns = ['_files/', '.tmp/', '__MACOSX/']

def should_process_file(parent_path, name):
    # Не обрабатываем файлы внутри исключенных папок
    for pattern in excluded_patterns:
        if pattern in parent_path:
            return False
    # Не обрабатываем сами *_files папки (только если это dir)
    return True
```

### Проблема 3: Rate Limiting (API ограничения)
**Описание:** Yandex Disk API имеет лимиты на количество запросов в единицу времени. При переименовании 100+ файлов подряд возможна ошибка `429 Too Many Requests`.

**Официальные лимиты Yandex Disk API:**
- **Неавторизованные запросы:** 100 запросов/час
- **Авторизованные (OAuth):** 10,000 запросов/день (~400/час)

**Решение:**
1. **Batch обработка с паузами:**
   ```python
   import time

   BATCH_SIZE = 10  # Переименовать по 10 файлов за раз
   PAUSE_SECONDS = 5  # Пауза между батчами

   for i in range(0, len(files_to_rename), BATCH_SIZE):
       batch = files_to_rename[i:i+BATCH_SIZE]
       for file in batch:
           rename_via_api(file)

       if i + BATCH_SIZE < len(files_to_rename):
           print(f"Пауза {PAUSE_SECONDS}с перед следующим батчем...")
           time.sleep(PAUSE_SECONDS)
   ```

2. **Обработка ошибок 429:**
   ```python
   def rename_with_retry(old_path, new_path, max_retries=3):
       for attempt in range(max_retries):
           try:
               client.move(old_path, new_path)
               return True
           except Exception as e:
               if '429' in str(e):
                   wait_time = 60 * (2 ** attempt)  # Exponential backoff
                   print(f"Rate limit hit. Waiting {wait_time}s...")
                   time.sleep(wait_time)
               else:
                   raise
       return False
   ```

3. **Прогресс-бар:**
   ```python
   from tqdm import tqdm

   for file in tqdm(files_to_rename, desc="Renaming files"):
       rename_with_retry(file['old'], file['new'])
   ```
