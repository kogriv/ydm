## Вопрос 1 — установленное задание отстало (единственное, что пишет)

`~/ydm_bisync_job.sh` на устройстве — монолит до PR #9: container-half
заинлайнен в `bash -c`. Из-за этого `job_run.sh` там **не выполняется вообще**,
а именно он пишет в `var/bisync.log` строки, добавленные в PR #15. То есть
guard уже принимает правильные решения — и по-прежнему молча.

```bash
bash tools/termux/install_job.sh install
```

Проверить, что доехало:

```bash
grep -n "log_decision\|BISYNC_LOG" ~/ydm_bisync_job.sh tools/termux/job_run.sh | head
```

Ожидаются четыре повода в логе, из которых один означает беду:

| строка | что значит |
|---|---|
| `skip_bisync (no_comparable_baseline)` | нет скана этого зеркала — проверить `--local-root` |
| `skip_bisync (baseline_unreadable)` | база не ответила — проверить базу |
| `block_bisync (...)` | guard остановил синхронизацию |
| `allow_bisync (error)` | **bisync прошёл без guard'а** — это issue #5, за этим и следить |

Дождаться одного цикла задания (~30 мин) и посмотреть:

```bash
tail -20 var/bisync.log
```

Нормальный прогон не пишет строки guard'а вовсе — только `run OK` от
`sync_bisync.py`. Пустота здесь — хороший знак, а не отсутствие логирования.

## Вопрос 3 — счётчик запросов, чтобы сверить с этой машиной

Секундомер на устройстве шумит, а счётчик запросов — одно и то же число на
обеих машинах. Если он совпадёт, значит правка доехала целиком; если нет —
разница в данных, а не в коде.

```bash
python3 - <<'PY'
import sys, io, contextlib, time
sys.path.insert(0, "tests")
from query_count import counting_queries
sys.argv = ["ydm_menu.py", "orphans"]
from tools import ydm_menu
buf = io.StringIO(); t = time.time()
with counting_queries() as q:
    with contextlib.redirect_stdout(buf):
        try: ydm_menu.main()
        except SystemExit: pass
print(f"{q.count} queries, {time.time()-t:.2f}s")
print(q.report())
PY
```

На снимке автора (144 МБ, 3 810 узлов) это **873** запроса против 54 568 до
правки. Здесь снимок другой, так что число будет другим — важен порядок и то,
что в отчёте наверху не окажется запроса, выполненного тысячи раз.
