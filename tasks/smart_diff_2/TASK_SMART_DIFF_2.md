# Задача: Smart Diff 2 — дифф в рамках синхронизируемого подмножества

*Дата регистрации:* 2026-01-30  
*Статус:* Open  
*Приоритет:* Medium  
*Источник требований:* перенесено из `issues/DESIGN_SYNC_TREE_AND_MANAGEMENT.md` (раздел «Sync‑дифф»)

---

## 1. Контекст

Задача **smart_diff** (`tasks/smart_diff`) реализована: строится снимок состояния облака на основе разных сканов с использованием окна свежести и композитного диффа.

**Smart Diff 2** — отдельная задача: расширить отчёт о расхождениях так, чтобы показывать только те пути, которые входят в **синхронизируемое подмножество** (с учётом `exclude-dirs` конфига Yandex Disk). То есть «sync-only» режим для `report diff`.

---

## 2. Цель

**Sync‑дифф (расхождения в рамках синхронизируемого):**

- **Команда (концепт):** например `ydm.py report diff --sync-only` или отдельная команда `ydm.py sync diff`.
- **Фильтрация:** только пути, входящие в «синхронизируемое подмножество»:
  - не исключённые целиком;
  - для частично синхронизируемых папок — только включённые ветки.
- **Вывод:** те же поля, что и у текущего `report diff`, но `missing_local` / `missing_cloud` отфильтрованы по этому подмножеству; в JSON без изменений структуры, только меньше записей и другие счётчики.

---

## 3. Входные данные

- Актуальный снимок облака (дерево папок/файлов из БД — smart diff / композитный снимок).
- Конфиг Yandex Disk на машине: `exclude-dirs` (и при необходимости другие параметры).
- Логика «включено, если не исключено» с учётом иерархии:
  - папка исключена ⇒ исключено всё внутри, если нет явно включённой дочерней;
  - для Yandex Disk: исключение папки исключает её целиком; включение подпапки — родитель не в exclude, нужные ветки не в exclude.

---

## 4. Требования к реализации

1. Режим `--sync-only` (или аналог) для команды отчёта о диффе.
2. При включении режима:
   - загрузить `exclude-dirs` из конфига Yandex Disk;
   - для каждого пути в результатах диффа определить, входит ли он в синхронизируемое подмножество;
   - оставить в выводе только такие пути (и скорректировать сводные счётчики).
3. Формат вывода не менять: те же поля и структура, что у обычного `report diff`; меняется только состав записей и итоги.

---

## 5. Связи

- **smart_diff** (`tasks/smart_diff`) — источник снимка облака и логики диффа.
- **sync_manager** (`tasks/sync_manager`) — общая работа с конфигом Yandex Disk, деревом облака и статусами sync (full/partial/excluded); при реализации sync-only диффа можно переиспользовать логику определения «синхронизируемого подмножества».

---

## 6. Резюме

| **Вывод** | Та же схема, что у `report diff`; меньше записей и обновлённые счётчики. |
