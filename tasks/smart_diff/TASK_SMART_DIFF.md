## 1. Проблема (Диагностика)

### Текущая ситуация

Команда `report diff` сравнивает последний cloud scan с последним успешным local scan. Это создает проблему неактуального сравнения в следующих случаях:

#### 1.1. Проблема с частичными сканами

**Сценарий:**
```bash
# Пользователь сканирует только одну папку
python3 ydm.py scan cloud --path "/Архив" --progress

# Эта папка отсутствует на локальном диске
# При сравнении:
python3 ydm.py report diff
```

**Результат:**
- `diff` использует последний cloud scan (который содержит только `/Архив`)
- Сравнение показывает, что все файлы из `/Архив` отсутствуют локально
- Но это не означает проблему синхронизации - просто эта папка не должна быть на диске
- **Сравнение становится неактуальным и вводит в заблуждение**

#### 1.2. Текущая логика выбора сканов

**Код в `get_diff()` (строки 1043-1052):**
```python
# Для чистоты берем последний cloud scan независимо от статуса
last_cloud = conn.execute("SELECT id FROM scans WHERE scan_type='cloud' ORDER BY id DESC LIMIT 1").fetchone()
last_local = conn.execute("SELECT id FROM scans WHERE scan_type='local' AND status='success' ORDER BY id DESC LIMIT 1").fetchone()
```

**Проблемы:**
1. ❌ Берется последний cloud scan **независимо от статуса** (может быть `interrupted`, `started`)
2. ❌ Берется последний cloud scan **независимо от полноты** (может быть частичный скан одной папки)
3. ❌ Нет возможности указать конкретные scan_id для сравнения
4. ❌ Нет механизма композиции данных из нескольких сканов

#### 1.3. Отсутствие метаданных о типе скана

**Структура таблицы `scans`:**
```sql
CREATE TABLE scans (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    timestamp DATETIME DEFAULT CURRENT_TIMESTAMP,
    scan_type TEXT NOT NULL,  -- 'meta', 'cloud', 'local'
    status TEXT NOT NULL,      -- 'started', 'success', 'failed', 'interrupted'
    duration REAL
);
```

**Проблемы:**
- ❌ Нет поля, указывающего был ли скан полным (`/`) или частичным (`/Архив`)
- ❌ Нет информации о том, какие папки были отсканированы
- ❌ Определение полноты скана требует анализа `scan_progress` или количества файлов

#### 1.4. Невозможность инкрементальных сканов

**Текущая ситуация:**
- Для актуализации данных нужно сканировать весь диск заново
- Это занимает много времени (часы для больших дисков)
- Увеличивает размер БД (дублирование данных)

**Желаемое поведение:**
- Сканировать только изменяемые папки
- Обновлять данные по конкретным папкам без полного пересканирования
- Сократить время и размер БД

**Метод 2: Аналитически (резервный)**

```python
def find_full_scans():
    """Находит полные сканы по количеству файлов."""
    # Найти верхнюю границу по количеству файлов
    # Все сканы с количеством > threshold считаем полными
    conn.execute("""
        SELECT scan_id, COUNT(*) as files_count
        FROM files 
        WHERE scan_type='cloud' AND type='file'
        GROUP BY scan_id
        ORDER BY files_count DESC
    """)
    # Взять 95-й перцентиль как threshold для полных сканов
```

#### Этап 2: Построение композитного снимка

**Подход A: SQL VIEW (рекомендуется)**
```sql
-- Создать временную VIEW для композитного снимка
CREATE TEMP VIEW composite_cloud AS
WITH 
-- Найти последний полный скан
base_scan AS (
    SELECT id FROM scans 
    WHERE scan_type='cloud' 
    AND id IN (
        SELECT scan_id FROM scan_progress WHERE path = '/'
    )
    ORDER BY id DESC LIMIT 1
),
-- Найти все частичные сканы после базового
partial_scans AS (
    SELECT s.id, s.timestamp
    FROM scans s
    WHERE s.scan_type='cloud' 
    AND s.status='success'
    AND s.id > (SELECT id FROM base_scan)
    AND s.id NOT IN (SELECT scan_id FROM scan_progress WHERE path = '/')
),
-- Для каждой папки найти последний скан
latest_folder_scans AS (
    SELECT DISTINCT 
        f.parent_path,
        MAX(f.scan_id) OVER (PARTITION BY f.parent_path) as latest_scan_id
    FROM files f
    JOIN partial_scans ps ON f.scan_id = ps.id
    WHERE f.scan_type = 'cloud'
)
-- Объединить: базовый скан + обновления из частичных
SELECT f.* FROM files f
WHERE f.scan_id = (SELECT id FROM base_scan)
  AND f.parent_path NOT IN (SELECT parent_path FROM latest_folder_scans)
UNION ALL
SELECT f.* FROM files f
JOIN latest_folder_scans lfs 
    ON f.scan_id = lfs.latest_scan_id 
    AND f.parent_path = lfs.parent_path;
```

**Подход B: Python-композиция (проще для начала)**
```python
def build_composite_scan(cloud_scan_id=None):
    """
    Создает виртуальную таблицу для сравнения.
    
    Returns:
        dict: {parent_path: scan_id} - маппинг папок на их последние сканы
    """
    # 1. Найти последний полный скан (или указанный)
    base_scan = find_last_full_scan(cloud_scan_id)
    
    # 2. Найти все частичные сканы после базового
    partial_scans = find_partial_scans_after(base_scan.id)
    
    # 3. Для каждой папки найти последний скан
    folder_to_scan = {}
    for scan in partial_scans:
        for folder in get_folders_in_scan(scan.id):
            if folder not in folder_to_scan or scan.timestamp > folder_to_scan[folder].timestamp:
                folder_to_scan[folder] = scan
    
    # 4. Вернуть маппинг: {parent_path: scan_id}
    # Базовый скан используется для всех папок, не в folder_to_scan
    return {
        'base_scan_id': base_scan.id,
        'folder_updates': folder_to_scan
    }
```

#### Этап 3: Обновленный метод `get_diff()`

```python
def get_diff(self, cloud_scan_id=None, local_scan_id=None, use_composite=True):
    """
    Сравнивает cloud и local сканы с поддержкой композитного снимка.
    
    Args:
        cloud_scan_id: Конкретный cloud scan ID (опционально)
        local_scan_id: Конкретный local scan ID (опционально)
        use_composite: Использовать композитный снимок (по умолчанию True)
    """
    # 1. Определить cloud scan
    if cloud_scan_id:
        cloud_scan = validate_cloud_scan(cloud_scan_id)
    elif use_composite:
        # Построить композитный снимок
        composite = build_composite_scan()
        cloud_scan = composite
    else:
        # Старое поведение: последний скан
        cloud_scan = find_last_cloud_scan()
    
    # 2. Определить local scan
    if local_scan_id:
        local_scan = validate_local_scan(local_scan_id)
    else:
        local_scan = find_last_successful_local_scan()
    
    # 3. Сравнить (с учетом композитного снимка)
    if isinstance(cloud_scan, dict) and 'base_scan_id' in cloud_scan:
        # Композитный снимок - использовать специальный SQL
        return compare_composite_scan(cloud_scan, local_scan)
    else:
        # Обычное сравнение
        return compare_simple_scan(cloud_scan, local_scan)
```

### Этап 3: Композитный снимок (базовая версия) ✅ **ЗАВЕРШЕН**

**Цель:** Реализовать построение композитного снимка из полного + частичных

**Задачи:**
1. ✅ Реализовать `build_composite_scan(cloud_scan_id=None)`
2. ✅ Реализовать `find_partial_scans_after(base_scan_id)`
3. ✅ Реализовать `get_folders_in_scan(scan_id)` для определения отсканированных папок
4. ✅ Реализовать SQL для композитного сравнения
5. ✅ Интегрировать в `get_diff()` с флагом `use_composite=True`
6. ✅ Тесты на реальных данных

**Оценка:** 6-8 часов  
**Фактическое время:** ~3 часа  
**Дата завершения:** 07.01.2026

**Реализовано:**

1. **Метод `get_folders_in_scan(scan_id)`:**
   - Возвращает множество всех `parent_path` значений из таблицы `files` для указанного скана
   - Используется для определения, какие папки были отсканированы в частичном скане

2. **Метод `find_partial_scans_after(base_scan_id)`:**
   - Находит все частичные (неполные) cloud сканы, которые произошли после базового полного скана
   - Возвращает список с информацией о каждом частичном скане (id, timestamp, status, root_path)
   - Исключает полные сканы (те, у которых есть `path='/'` в `scan_progress`)

3. **Метод `build_composite_scan(cloud_scan_id=None)`:**
   - Строит композитный снимок из базового полного скана + обновлений из частичных сканов
   - Если указан `cloud_scan_id` - использует его как базовый (валидирует, что он полный)
   - Если не указан - автоматически находит последний полный скан
   - Для каждой папки определяет последний актуальный скан (базовый или частичный)
   - Возвращает структуру: `{base_scan_id, folder_updates: {parent_path: scan_id}, ...}`

4. **Метод `_compare_composite_scan(composite, local_id, exclude_dirs)`:**
   - Выполняет сравнение композитного облачного снимка с локальным сканом
   - Использует UNION подход для объединения данных из базового скана и обновленных папок
   - Для каждой папки проверяет соответствующий скан (базовый или обновленный)
   - Применяет фильтрацию исключенных директорий и системных файлов

5. **Метод `_compare_simple_scan(cloud_id, local_id, exclude_dirs)`:**
   - Простое сравнение двух сканов (без композитного режима)
   - Вынесен в отдельный метод для переиспользования

6. **Обновлен метод `get_diff()`:**
   - Добавлен параметр `use_composite=True` (по умолчанию включен)
   - Логика выбора режима:
     - Если указан `cloud_scan_id` - всегда используется простой режим
     - Если `cloud_scan_id` не указан и `use_composite=True` - пытается построить композитный снимок
     - Если композитный снимок не удалось построить - fallback на последний скан
     - Если `use_composite=False` - использует последний скан (старое поведение)

7. **Добавлен флаг CLI `--no-composite`:**
   - Позволяет отключить композитный режим из командной строки
   - Используется для обратной совместимости и тестирования

**Особенности реализации:**
- Композитный режим работает автоматически, если не указан конкретный `cloud_scan_id`
- При указании `cloud_scan_id` всегда используется простой режим (для предсказуемости)
- SQL запросы оптимизированы с использованием UNION для объединения данных
- Обработка перекрытий папок: используется более поздний скан (выше scan_id)
- Fallback на простой режим, если композитный снимок не удалось построить

**Примеры использования:**

```bash
# Композитный режим отключен (старое поведение)
python3 ydm.py report diff --no-composite

# Явное указание cloud scan (всегда простой режим)
python3 ydm.py report diff --cloud-scan-id 42

# Композитный режим с указанием local scan
```

## 6. Риски и ограничения

### Риски

1. **Производительность композитного снимка:**
   - Большие SQL-запросы могут быть медленными
   - **Митигация:** Использовать индексы, временные таблицы, кэширование

2. **Сложность отладки:**
   - Композитный снимок сложнее понять, откуда данные
   - **Митигация:** Добавить логирование источников данных

3. **Конфликты при перекрытии папок:**
   - Могут быть неочевидные случаи
   - **Митигация:** Четкая документация логики приоритетов

### Ограничения

1. Композитный снимок работает только для cloud scans (local scans всегда полные)
2. Требуется хотя бы один полный cloud scan для базы
3. Частичные сканы должны быть успешными (`status='success'`)

## 7. Примеры использования

### Пример 1: Автоматическое сравнение (текущее поведение)

```bash
# Использует последний cloud scan и последний успешный local scan
python3 ydm.py report diff
```

**Результат:**
- Берет последний cloud scan (независимо от статуса)
- Берет последний успешный local scan
- Сравнивает их

### Пример 2: Явное указание cloud scan ✅ **РЕАЛИЗОВАНО**

```bash
# Сравнить конкретный cloud scan с последним успешным local scan
python3 ydm.py report diff --cloud-scan-id 42
```

**Результат:**
- Использует указанный cloud scan (42)
- Валидирует, что scan существует и является cloud scan
- Берет последний успешный local scan
- Сравнивает их

### Пример 3: Явное указание обоих сканов ✅ **РЕАЛИЗОВАНО**

```bash
# Сравнить конкретные сканы
python3 ydm.py report diff --cloud-scan-id 42 --local-scan-id 10
```

**Результат:**
- Использует указанный cloud scan (42)
- Использует указанный local scan (10)
- Валидирует оба скана (существование, тип, статус для local)
- Сравнивает их

### Пример 4: Умное сравнение (планируется в Этапе 3)

```bash
# Умное сравнение (автоматически найдет полный + частичные)
python3 ydm.py report diff
```

**Результат (после реализации Этапа 3):**
- Найдет последний полный скан (например, scan_id=40)
- Найдет все частичные сканы после него (scan_id=41, 42, 43)
- Построит композитный снимок
- Сравнит с последним успешным local scan

### Пример 5: Только полные сканы (планируется)

```bash
# Отключить композитный снимок
python3 ydm.py report diff --full-only
```
