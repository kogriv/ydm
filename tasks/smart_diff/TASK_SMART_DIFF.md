# Smart Diff: композитный снимок для `report diff`

*Статус:* реализовано (07.01.2026). См. [HOW_TO_USE.md](HOW_TO_USE.md)
for actual usage; this doc covers the problem and the design.

## Проблема

`report diff` сравнивал последний cloud scan с последним успешным local
scan, независимо от того, был ли cloud scan полным или частичным
(например, `scan cloud --path "/Archive"`). Если последний скан покрывал
только одну папку, diff показывал, что всё остальное "пропало локально"
— ложная тревога, а не реальная проблема синхронизации.

Дополнительные проблемы исходной логики:
- Последний cloud scan брался независимо от статуса (мог быть
  `interrupted`/`started`).
- Не было способа явно указать, какие сканы сравнивать.
- Не было механизма объединения данных из нескольких сканов.

## Решение

**Композитный снимок**: базовые данные берутся из последнего *полного*
cloud-скана (см. [FULL_SCAN_HEURISTICS.md](FULL_SCAN_HEURISTICS.md) — как
определяется, что скан "полный"), а для папок, у которых есть более
свежий частичный скан, данные берутся из него.

Ключевые решения по реализации:
- `build_composite_scan(cloud_scan_id=None)` строит маппинг
  `{base_scan_id, folder_updates: {parent_path: scan_id}}`;
  `find_last_full_scan()` находит базовый скан (эвристика или явный
  `--cloud-scan-id`).
- При перекрытии папок (например, отсканированы и `/Archive`, и
  `/Archive/2024`) побеждает более специфичный (глубокий) путь, а при
  равной специфичности — более поздний скан.
- Композитное сравнение построено на временных таблицах + `UNION` (не
  на построчных Python-запросах) ради производительности на больших
  деревьях; результат кэшируется в `Analyzer` на 5 минут.
- `--cloud-scan-id`/`--local-scan-id` явно задают конкретные сканы
  (в этом случае композитный режим не используется — предсказуемость
  важнее). `--no-composite` отключает композитный режим целиком (старое
  поведение: просто последний cloud scan).

## Ограничения

- Композитный снимок работает только для cloud scans — local scans
  всегда берутся целиком (locally there's no "partial scan" concept).
- Нужен хотя бы один полный cloud scan как база.
- Частичные сканы, участвующие в композите, должны быть `status='success'`.

## Связанные задачи

- Управление синком (`tasks/sync_manager/`) может со временем опираться
  на композитный снимок для инкрементальных обновлений вместо полного
  пересканирования.
